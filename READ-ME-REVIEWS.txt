SANCHARI HUB - CUSTOMER REVIEWS SETUP (NO NODE.JS)

1. Create a free project at https://supabase.com (free-tier limits apply).
2. In Supabase open SQL Editor -> New query. Paste the contents of supabase-reviews-setup.sql and click Run.
3. Open Project Settings -> API Keys / Data API. Copy the Project URL and publishable key (or legacy anon key). Do NOT use a secret or service_role key.
4. Open index.html in a text editor. Set REVIEW_DB_URL to the Project URL (for example, https://your-project.supabase.co) and REVIEW_DB_KEY to the public publishable/anon key. A copied URL ending in /rest/v1/ is also accepted. Save the file.
5. Test the review form from your website. Successful new submissions are published automatically; no approval step is required.
6. The owner can hide an individual review from Supabase Table Editor -> traveler_reviews by setting approved to false. Public visitors cannot edit, delete, or change a review's approval status.

The site works without Node.js. A database connection is required for reviews to be shared across visitors.

EXISTING PROJECT: ENABLE AUTOMATIC PUBLICATION

The website cannot change a database policy with its public key. In the Supabase dashboard for the existing project:
1. Open SQL Editor -> New query.
2. Paste the complete contents of supabase-reviews-auto-publish.sql.
3. Click Run using the project's owner/admin access.

The migration changes approved's default to true and replaces the old pending-only insert policy in a single transaction. It is safe to run more than once. Older unpublished reviews remain hidden; this migration does not approve them.

The updated supabase-reviews-setup.sql also supports automatic publication for new projects and can be rerun on the existing table. No admin, secret, or service_role key belongs in index.html or chat.

Keep the "Public read approved reviews" SELECT policy enabled. The public client reads only the five granted review columns and inserts only name, trip, rating, and experience. It must not select, filter, or set approved. New rows receive approved=true from the database; only the database owner can change approval status afterward.

After the SQL change and website deployment, submit a genuine review and verify that it appears immediately and remains visible after refreshing the page. Current pages refresh shared reviews every 15 seconds while visible and when returning to the tab. Pages loaded before the website update need one refresh to load the new code.
